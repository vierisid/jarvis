# Third-Party Notices

## Scope

This file covers **third-party source vendored into this repository** -- code that ships in the Jarvis source tree at build time (Activepieces under `src/workflows/activepieces/`, and Unicode's confusables mapping data in `src/authority/confusables-data.ts`). Each vendored project is distributed under its own license, reproduced below. The combined work (Jarvis) is distributed under the [Jarvis Source Available License 2.0](LICENSE); the third-party portions retain their original licenses for any party who extracts them as a standalone work. It also covers the Go modules the sidecar binary links (last section).

**Not covered here:**

- **npm runtime dependencies** (e.g. `socket.io`, `nanoid`, `bun:sqlite`). These are listed in `package.json` and resolved into `node_modules` at install time; their licenses live next to the published packages and are not reproduced in this file. Every package the locked install puts in `node_modules`, dev dependencies included (the Docker image ships them), is held to the same license policy as the pieces trees below by `scripts/check-root-licenses.ts`, which a test runs. One known violation, `edge-tts-universal` (AGPL-3.0, used for Edge text-to-speech), is listed there while replacing, isolating or accepting it is decided (#1166). An install from npm resolves the version ranges afresh, so the check vouches for the locked versions only.
- **Community Activepieces pieces** installed at runtime into `~/.jarvis/pieces/` from the curated catalog. Each piece carries its own license metadata; the catalog (`src/workflows/pieces-library/catalog.ts`) only lists semver pins, not vendored source. Each install is checked against the same license policy as the hosted tree below, and a piece it denies is refused and removed (at install) or held: removed from `node_modules` and not loaded (at boot).
- **The engine's build dependencies** (`src/workflows/runner/engine-runtime/engine-staging.lock`), which the engine bundle and the vendored core pieces' bundles compile in. They are held to the same license policy by a test; LGPL `openpgp` (core crypto piece) and MPL-2.0 `exifreader` (core image helper) are used unmodified.

**Hosted shared pieces tree.** On hosted installs we build the community catalog once per version and run it for every tenant, so that tree is covered by its own generated file: `scripts/build-shared-runtime.ts` writes `<out>/pieces/THIRD_PARTY_NOTICES.md` next to it, listing every installed package with its license and reproducing the license and notice files each package ships. LGPL and MPL packages, used unmodified, are listed in their own section. The build refuses the tree when the license policy (`src/workflows/pieces-library/license-policy.ts`) denies any package in it: only permissive licenses, LGPL and MPL are allowed, and a package with no usable license declaration needs a reviewed entry. Pieces left out for that reason are listed, with the reason, in `src/workflows/pieces-library/catalog-overrides.ts`: `EXCLUDED` for pieces not offered anywhere (today Actual Budget, whose `@actual-app/core` dependency pulls GPL-3.0-only `hyperformula` and AGPL-3.0-or-later `ua-parser-js`), and `SHARED_BUILD_EXCLUDED` for pieces left out of the hosted tree only. The weekly catalog sync runs the same check first.

## Sidecar (Go modules)

The modules are the ones `go list -deps` reports for the linux, darwin and windows builds; `sidecar/go.mod` requires exactly these, and `scripts/sidecar-notices.test.ts` fails when it requires a module or version this section does not list, so a new or bumped module gets its license reviewed here (a person reviews the license; the test checks only that it is listed). `go.mod` should require only modules the sidecar links: test-only and unlinked modules appear only in `go.sum` and are not listed.
