## Result

Today's main goal has an anchored title, measured count and shared progress segments. **What's next?** replaces only the body with a concise recommendation, **Add to Today** and **Back to goal**. Escape returns locally, and focus follows the return control. Only the main goal remains when Pebble opens; the existing companion host keeps the card above the conversation. Long content wraps and scrolls without shrinking the controls.

Acceptance first confirms locally, then names the same item in a blue destination cue at the hero. The existing front decision stays in place. Confirmation requires both a correlated owner receipt and exactly one matching item in a fresh queue projection. Accepting or resolving the item never increments goal progress. The preview's separate **+1 partner** control represents an actual new measurement.

The UI locks an attempt synchronously, ignores late results for a different identity and refuses success for mismatched request/recommendation/goal revisions, missing receipt IDs, a different destination title, duplicate queue identities or stale queue data. Unknown/lost responses are not automatically retried. A historical accepted projection renders quietly without replaying its cue. The displayed recommendation expires while the page remains open.

No live provider, endpoint, goal engine, queue writer, email or workflow execution is introduced. The default released dashboard is unchanged. **Implementation is complete; live activation is not enabled.**

**F-13 owns the durable recommendation and acceptance adapter.** Its responsibilities:

- Supply stable recommendation/goal IDs, revisions, concise title/rationale, qualified evidence, expiry and the current recommendation state. Preserve Q-18's intent and evidence; do not infer progress or turn ambiguous work into execution permission.
- Revalidate ownership, goal revision, recommendation freshness and readiness at acceptance time. UI checks and source flags are not authorization boundaries.
- Persist idempotency and a canonical receipt before returning success. Echo the exact request correlation fields and map the durable work item to its decision identity/title. Reconcile lost responses and concurrent clients. A component-local lock is not durable deduplication.
- Append to the authoritative queue without displacing an existing front decision, publish a fresh queue projection, and later preserve the same item's title/identity as it advances. The UI never writes optimistic queue items or counts.
- Reconcile an unresolved acceptance before offering another attempt. A fresh revision must mean genuinely refreshed authoritative data. Provide `refresh` if the owner supports recovery. On remount, supply accepted state when the receipt is already durable so the destination cue does not replay.

**F-15 owns measured values.** Supply `BriefMeasurement` values, units, targets, timestamps and provenance; null means unknown. Main and driver bars reuse D-09's `GoalSegments`: red below 20%, amber below 40%, blue below 75%, green from 75%, with gray remainder. Positive weekly change stays a distinct green signal. Do not derive a signed-partner count from a title or a review score. D-24 should reuse these same value/bar primitives when the Goals room is built.

Live display requires a `live` source and ready/enabled `goalMeasurements`. Acceptance additionally requires `recommendations` and `decisions`; loss of these capabilities disables it. Missing owners produce unavailable/unsupported states, not sample data. Preview accepts only `fixture` sources.
