## Use in later D tasks

```tsx
const ref = useBriefMotion<HTMLDivElement>(
  { transform: `translateY(${open ? 0 : 8}px)`, opacity: open ? 1 : 0 },
  { kind: "reveal", active: open },
);
return <div ref={ref} inert={!open} aria-hidden={!open}>{content}</div>;
```

Keep the wrapper mounted during its exit. The hook owns only the declared inline properties; do not also transition those properties in CSS. Keep the property set constant between calls. Focus, selection, `inert`, accessible expansion and content are owned by the room, not an animation callback. Give non-hover users a normal click/keyboard path.

Use `press` for a surface overlay, `reveal` for a short translation/fade, `selection` for an indicator, `reflow` for a bounded surface, `transfer` for the same object between fixed slots, and `settle` for a short finish. No text scaling. Width/height animations are allowed only on the bounded surfaces that need them; do not animate a whole page's layout. Keep readable text in an anchored column. `briefMotionVariables` exposes the same tokens for scoped CSS consumers; there is no parallel engine, global style override or new dependency.

The final style is committed before native animation begins. A new intent reads the current computed style, cancels the old animation, and starts one replacement. Stale completion cannot change selection or cancel the replacement. Unmount restores owned styles; expected cancellation rejections are consumed. Missing WAAPI falls back to the same immediate endpoint. Unchanged endpoints and first mount do not animate. Theme colors keep D-03's immediate surface/ink change.

## Evidence and limits

See `D-04.json` and `evidence/D-04/`. The browser harness records rAF intervals, input cadence, per-element WAAPI retarget samples, anchor positions, endpoint parity and remaining animations. These are actual browser observations, not a DevTools CPU/GPU capture or a 60fps claim. Synchronous retarget samples may differ by subpixel rounding for layout dimensions.

Ten recorded cases pass: Light/Dark × wide/compact × standard/reduced, plus native 390px Light standard and Dark reduced. Each case completes 20 cycles (40 intents across six examples), has zero remaining animations, matching final endpoints and zero measured anchor drift. The maximum synchronous retarget difference is 0.01px, from width rounding. The five reduced cases record zero-duration transitions. `browser-summary.json` is readable in the PR; `browser-traces.json.gz` contains the full 1,524,675-byte JSON trace, compressed without loss. Its uncompressed SHA-256 is `483b897be8591f0e6f499f4cb70c63231db6ea45d69116bff045181da6b5eefa`. Read it with `gzip -dc docs/brief-delivery/evidence/D-04/browser-traces.json.gz`.

Screenshots: `light-wide.png`, `light-reflow.png`, `dark-wide.png`, `dark-narrow.png`. Viewport captures are retained because this browser's image capture does not cover the full emulated document height. No horizontal overflow was observed at 390px. The edited sample draft survived conversation close/reopen.

Unit tests cover reversal ordering, stale callbacks, cancellation, live media-query changes, reduced-motion precedence, StrictMode cleanup, unchanged endpoints and legacy/preview isolation. Two intentional mutations were rejected: cancelling before reading the visual position, and ignoring reduced motion. Source was restored and the full targeted set rerun.

Browser checks use the local reduce-only preview setting through the same hook. An actual OS setting change is covered by the media-query unit test, not certified through browser emulation. Browser evidence is Chromium only. Velocity continuity, low-end device performance, screen-reader behavior and full-room focus/scroll journeys are not claimed. Subsequent room tasks must verify their real composition and focus restoration.
