## Integration for Lapo and the next agent

Continue D-16's authenticated, account-and-vault-scoped `WorkflowCreationController` above room navigation. Its optional `ingredients` field is backward compatible with saved D-16 state. `setIngredients()` copies and validates public selections; the controller saves them before submitting and keeps an uncertain request independent of later edits. Retire the controller on ownership change as before.

Supply `WorkflowCreationBinding.ingredients` with an `IngredientCatalog` whose `source` and `scopeId` match that controller. A mismatched binding is not displayed. The room remains opt-in through D-16's registration, and activation still needs F-07, F-08, scoped host integration and D-33 release verification.

The host owns catalog loading and caching:

1. Call `readIngredientCatalog(() => currentCapabilities, abortSignal, authenticatedFetch)` once on demand, not every render or on an interval. Construction does not fetch. Keep loading/error state explicit. Abort and ignore stale results on account/vault change; never share a catalog across users.
2. The reader pages `/api/brief/composition-ingredients` using F-08's public discovery. Only that endpoint grants selectable connections/actions and their installed version/action-contract pins. Missing capability, failed pages, duplicate identity or the 10,000-entry bound rejects the snapshot rather than presenting a partial list as complete. Each request has a 15-second bound.
3. The existing public `/api/workflows/pieces/library` supplies optional service names and uninstalled-package rows. Catalog metadata cannot grant selection. Its failure leaves F-08 discovery usable with package identifiers as group labels. No connection `value`, private display name, credential metadata, OAuth token, auth schema or executable action schema is read for this UI.
4. Discovery currently exposes only active, compatible, authorized connections. With none available, the menu directs the user to Connected workspace. Do not infer that an installed library node has a connected account. Missing-account and unavailable row treatments are demonstrated with representative fixtures; richer live reasons require an explicitly safe provider projection, not access to private connection records. F-08 remains responsible for authoritative account/auth validation on submission.
5. Library grouping uses the real service/package catalog. There is no fabricated category taxonomy or copied 600-piece catalog in this branch. Query and selected service stay when the picker closes/reopens. Catalog refresh does not replace selected pins. If a selected row's version changes, the row asks the user to remove and explicitly select it again.
6. The `CompositionRequest` includes `ingredients` only when nonempty. `createCompositionPort` checks F-08 before such a POST; receipt lookup still works with F-08 off. Receipt ID, text/name and ordered canonical ingredients must match before navigation. Read-only recovery must not be turned into a new request with a different selection.

No new integration capability is added. Uninstalled and unavailable rows cannot install, connect or submit themselves. All labels are plain React text, not HTML. Up to 64 selections retain typed identities, so the same ID used by a connection and action does not collide.

## UI behavior

- One 400px anchored menu, clamped to the viewport, with shared Light/Dark menu material and the approved sharp upper-right corner. It follows the invoking theme and observed workspace/composer geometry.
- Persistent tabs stronger than row hover, one search input, real service filter, selected checkmarks and a quiet count. No second prompt or page transition.
- 44px plus/send controls keep their bottom inset and footprint. A measured optional ingredient slot keeps prompt text above wrapping chips; a large chip set scrolls inside 112px. The existing no-chip composer remains 56–104px. Extremely long prompt/selection combinations can increase the creation group's natural height rather than shrinking type or hiding controls.
- Each chip has a 32px removal target. Removal focuses a neighboring chip, then the prompt when the last one goes. Escape/Done restore the plus; leaving the non-modal picker continues into the composer. Outside focus/click dismisses without stealing focus.
- Entry and exit use reversible 180ms opacity/translation with no text scaling. OS reduced motion removes the transition. Close marks content inert immediately and removes the portal after exit. Reopening during exit reuses one portal.
- Success clears only a matching prompt **and** selection. Changed text or ingredients survive a prior request's completion. Invalid saved selection state blocks writes and submission rather than replacing an uncertain record.
