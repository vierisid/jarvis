# D-31 — Build Billing from the existing read model

D-31 replaces the opt-in Brief Billing placeholder with the approved plan, usage, payment method and history view. It reuses the existing shared billing store, hosted usage hook, currency/state helpers and external browser handoff. No billing write endpoint, price, entitlement, portal policy or hosting schema changes. D-32 is not included.

## Behavior and integration

| Area | Canonical behavior |
| --- | --- |
| Plan and renewal | Existing billing-view helpers; correct currency exponents and quantity. Mixed currencies/intervals are itemized, never added into one total. Trial, grace, expired grace, cancellation and incomplete payment remain distinct. |
| Usage | Existing six-hour and weekly percentages. Null is unavailable; old readings are labeled “Last reported usage.” Restricted accounts show the existing appeal copy without implying a window reset restores access. |
| Payment | Canonical brand, last digits, default and expiry; unreadable methods differ from an empty method list. |
| History | Canonical payments/refunds and gross including tax. HTTPS document URLs only, accessible table headers, narrow layout, 12-row expansion and stable payment identity through new reads. |
| Actions | Existing supplied URLs and `openExternal` / `openedOrHandedOff`. Cancellation remains reachable for active/trial subscriptions, and scheduled cancellation offers Resume. Blocked browser opening reports recovery without claiming a billing mutation succeeded. |
| Availability | Explicit loading, self-hosted, missing, old-response and stale views. No sample invoice or price is a live fallback. Preview/live mixing fails closed. |

Merge prerequisite: **D-01**. Enable prerequisites: **none**. The room-local registration supplies `Body: BillingWorkspace` through the existing opt-in Brief route. The central registry, default dashboard entry and capability defaults are unchanged; this is not a production rollout. Existing daemon authentication, system-owned hosted configuration and browser host integration remain the owners.

The live component mounts `useBilling` and `useHostedBudget`; the shell banner and Billing continue to share the same billing store. Reads are GET-only. Returning to the browser refreshes through the existing store. The explicit preview fixture bypasses both hooks and only records external destinations.
