## Behavior and boundaries

- Stable tutorial target IDs and `brief:v1:*` progress IDs use the existing progress, complete, dismiss and replay owners. Failure to save a step keeps the current slide. Focus follows the remounted Next/Finish button.
- The prompt and exact request key are written before F-07 POST. A lost response/reload reuses that key. Failed/blocked jobs keep the editable task; another explicit attempt receives a new key. No empty workflow creation, publish, enable, run, chat send, authority grant or OAuth endpoint is added.
- Draft review carries the F-07 `flowId`/`versionId`. The shared leave guard runs before a synchronous route commit; capability, destination and account ownership are rechecked after the guard. A failed handoff or final storage/status write retains the prompt and receipt.
- Hosted setup still omits provider selection; local/BYOK configuration remains available; the interview stays written. Tutorial replay does not reset setup or profile. The active Brief wizard survives peer completion updates, and peer resets restart its tour while retaining the unsent task.

## Optional host contract

`registerOnboarding()` without a host returns no registration. Production daemon registration and activation remain unchanged/off. F-01 gates `onboarding` on enabled `workflowComposition` (F-07), and the host readiness callback must confirm targets, progress and draft handoff.

D-33/F-28 must supply one `OnboardingDraft` per authenticated account/vault to `<OnboardingGate brief={draft}>`, only for a composed Brief host. `brief=1` selects this path; without the adapter or with the old shell flag, the existing gate runs. The host supplies current capability snapshots, real room availability, the existing dirty-draft guard, a synchronous route commit, and account-scoped session storage. Dispose the controller when account/vault ownership ends, not on ordinary room navigation. Rerender the host when capability access changes. Session storage failure blocks new submissions rather than losing their idempotency key. A new browser session does not restore an unsent session-local prompt.

`ONBOARDING_TARGETS` exports stable `data-onboarding-target` values and Brief routes for the assembled controls. The existing tutorial remains a clearly labelled, static dashboard preview; it never clicks the real controls. Host assembly must attach the same IDs and verify their real destinations before reporting readiness. No redesigned checkout/trial, live release, D-room assembly or F-27 reconciliation is included.
