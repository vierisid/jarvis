## Delivered behavior

| Approved field               | Canonical owner                                                                                                                        |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Full name                    | F-23 explicitly reports unavailable, owned by sign-in identity. Disabled with an explanatory hint; never inferred from preferred name. |
| What should Jarvis call you? | `preferred_name`                                                                                                                       |
| Company                      | `company`                                                                                                                              |
| Role                         | `work_role`; legacy multiline text is retained in a compact 44px textarea.                                                             |
| What are you building?       | `current_projects`                                                                                                                     |

The room uses shared accessible controls, 44px compact fields and 96px context areas, two-column desktop geometry, reserved validation/status space and fixed Save/Saved/Retry width. The secondary action also reserves Cancel/Reload width. Actions wrap at narrow widths without squeezing labels. Other existing profile answers and interview facts stay with the canonical owner; partial patches never replace the whole profile.

The scope-bound controller retains raw drafts outside the mounted room. Polling never advances a dirty draft's comparison revision. Typing during a save stays unsaved after the submitted values are confirmed, including returning a field to its old value. Stale reads preserve drafts and disable writes. Permission, capability, or scope loss purges old values and cancels pending callbacks.

Explicit saves validate the five editable canonical IDs and send `{revision, answers}` to F-23. A 409 retains the draft and requires explicit discard/reload. Failed or lost responses remain unconfirmed. **Retry save** first rereads the owner and only retries an unchanged revision or an exact match for the previous attempted patch; an intervening correction is never overwritten. There is no automatic mutation retry. Readback must match before the button says Saved.

Cancel and departure ask before discarding edits. Cancel only replaces the draft after a successful fresh read. A native modal supports Escape, safe initial focus, and focus return. Account-menu and sidebar navigation share the same guarded shell. Saving blocks departure. Browser unload warns while dirty; full browser reload intentionally does not persist drafts in local storage. Account-menu return and room remount read canonical data.

## Integration and activation

Merge prerequisite: **D-01**. Enable prerequisite: **F-23**. Production remains unchanged and disabled. The preview never substitutes for a missing live provider.

The host must:

1. Create `createProfilePort(scopeId, { request, canWrite })` using its authenticated, account-bound transport. F-23 still owns authorization and persistence.
2. Retain one `ProfileController` for that scope, and retire it on logout/account/transport replacement or permission change. Do not reuse a transport across accounts.
3. Install `guardProfileNavigation(shell, controller)` at the outer shell, so sidebar, account menu, and Profile receive the same guarded port. Other route sources (Back, voice, deep links) must call `controller.navigateAway(() => applyRoute())`; await/callback cancellation must be respected.
4. Supply `profileRegistration` with the exact scope, `source: "live"`, controller and current capability snapshot. The room requires enabled `profileSettings` and the guarded shell. Missing, unsupported, mismatched, or disabled bindings fail closed.
5. Verify the combined authenticated runtime and all navigation entry points before activation. The sibling F-23 modules are not imported into the shipped D branch.

The actual F-23 v1 HTTP shape is consumed through a narrow transport boundary. The optional integration proof imports the pinned provider only in a separate test process, initializes a temporary SQLite vault and secrets directory, then removes them. It uses actual route handlers and canonical persistence, with no live daemon, network request, or account write.
