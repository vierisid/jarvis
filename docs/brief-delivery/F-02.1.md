# F-02.1: Preserve conversation API response headers

Date: 2026-10-05

Branch: `brief/f-02-1`, stacked on `brief/f-02` at
`1b477587eb6471fa32ee54ca67d2b783408e343e` (PR #714).

## Change

F02 conversation responses bypassed the daemon's shared JSON helper and omitted
its configured CORS headers. A browser client at the allowed origin on a separate
port in an open-access development setup could not read those responses.

Conversation routes now receive the existing JSON helper and add
`Cache-Control: no-store` to its response. Success, validation, missing-record,
disabled, unsupported and provider-failure responses retain the configured
headers and their original status codes.

This is a backend correction. It adds no UI or schema change, enables no feature,
and does not expand the existing authentication or cross-site write policy.
Merge this follow-up after F02; keep both PRs unmerged until the planned stack is
ready. Reverting this follow-up restores the previous response construction.

## Verification and reproduction

`Access-Control-Allow-Origin: http://localhost:4381`, received no header.
It passes after the fix and exercises 200, 201, 400, 404, 501 and 503 responses,
including both disabled and failed providers. It also asserts JSON content type,
allowed methods/headers and `no-store`, restoring the prior CORS origin afterward.
