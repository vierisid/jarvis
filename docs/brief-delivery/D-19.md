# D-19 · Run history with one inline detail

Selecting a run now updates one inline inspection card. It never opens a second overlay or substitutes the latest run. The history distinguishes queued, running, paused, failed, cancelled, uncertain and succeeded, with step inspection, partial action receipts, waitpoints and recorded context available in the same card.

This is an optional, disabled Brief module on the approved unmerged D stack. The production room registry and legacy workflow route are unchanged. F-21 and authenticated host integration must be complete before activation. The preview uses illustrative in-memory data; Run workflow executes nothing.

## Implementation

`WorkflowViewHeader` shares the workflow name, action and navigation geometry with the actual D-18 editor. The active underline moves locally; reduced motion uses immediate placement. Canvas still retains rename, Save, Discard, Arrange, Undo and its dirty-navigation guard. Context remains the D-20 handoff in this preview.

`WorkflowRunsController` owns an account/flow/version-scoped history and selection by immutable run ID. Each selection clears the previous detail immediately. Aborted or late responses cannot replace the currently selected result, even when a provider ignores cancellation. A missing deep link remains missing rather than opening another run. Historical version IDs are retained and compared with the matching history record, not rewritten to the current editable version. Loading, empty, unsupported, unavailable and stale reads stay distinct.

List refresh merges by run ID, retains loaded earlier pages and uses the provider's opaque cursor. The selected ID and stored history/detail scroll positions survive ordinary room returns, chat and sidebar changes when the host retains the controller. Visible mounted rooms refresh read projections every eight seconds. Refresh never submits a command.

Manual Run is optional. While the supplied command is pending it is single-flight. A matching acknowledgement inserts and selects its exact returned run ID, then reads that run. An unconfirmed request stays locked through refresh and room remount. There is no retry, replay, resume or cancellation policy added here. A late acknowledgement cannot navigate an unmounted room. The host must persist/reconcile commands across full application reloads before supplying this port.

The card reads only an already-redacted presentation projection. Strings render as text, and fields explicitly marked redacted display `Redacted`. Receipt descriptions, partial effects, waitpoints and removed context remain inspectable. No raw error strings, effect arguments, credentials or bearer resume URLs are mapped by this module. The UI is not a substitute for server-side redaction.

History and detail scroll separately at desktop widths. Chat-open rows compact into two lines; the inspection remains inline and the workspace corner is reserved for Pebble. Below 450px available width, history and detail stack in the scrolling work area. Keyboard focus and reduced motion use the shared controls.
