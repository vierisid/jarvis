## What changed

The existing `WorkflowEditor`, `useWorkflowEditor`, tree serializer, typed settings, variable picker, draft save and undo remain in use. An optional workspace presentation places the inspector beside the graph, with the approved sharp upper-right corner, type and theme tokens. Default legacy presentation stays horizontal and modal; Brief auto-layout is vertical. Authored node coordinates remain authoritative in either editor.

Configure retains typed fields, connection choices, router conditions, loop inputs, error handling and advanced options. Input shows configured input separately from the existing **sample input override**. Output uses the existing **sample output** editor and its test controls. Those samples are not presented as actual historical run outputs. Inspector sections remain mounted when changing tabs, closing the inspector and changing the shell; unfinished sample JSON is cached per node and tab for the scoped editor lifetime, including when selecting another node.

A scoped request/portal context keeps an authenticated owner's editor separate from fixture data without replacing global fetch. Pickers inherit the Brief theme. The unchanged legacy route defaults to its original network request and body portals. Ctrl/Cmd+Z in Brief is scoped to the editor and does not intercept contenteditable or conversation typing. Selection uses the entire detached chain, not just its first node. Enter/Space opens a focused node's inspector; its close control returns focus to that node.

The canvas retains its zoom and focal point during reflow. At a dense endpoint, it pans the same graph only as needed to keep the selected node's center reachable. It does not refit the whole graph or recreate the edit buffer. Zoom/Fit remain 44px controls. The inspector is 320px beside the canvas; below 650px available work width it stacks beneath the graph in a scrollable working area. Canvas and inspector reserve the workspace corner for Pebble.

Run workflow, workflow name and Canvas/Runs/Context navigation stay in the header. Rename, Save, Discard, Arrange and Undo remain available. The body is inert during a save so a server echo cannot overwrite another edit made during that request. Header navigation requires saving/discarding draft changes first. Run is disabled for unsaved or mismatched versions and repeated submission is locked pending the host's run reconciliation.

### Bounded editor repairs

The new real-editor tests exposed existing defects relevant to this step:

- A published version was changed to DRAFT locally before save, causing PATCH instead of creating a draft. Its LOCKED identity is now retained until the existing POST-versions path succeeds.
- Settings mutations and selection only handled the head of a detached chain. Descendants now select, edit and retain their saved positions. Moving a detached descendant uses the correct position store.
- Detached-chain insertion now uses the owning tree and reserves step names across all roots. Deleting a detached descendant preserves its neighbors; Undo restores the same chain.
- Discard restores the last saved workflow name rather than the already-edited version object.

These repairs change editor behavior only. They do not change workflow runtime, execution policy or graph wire format.

## PR review corrections

- **R1:** Every node-creation path now scans the same complete graph namespace, including all detached descendants. Inserting into a detached chain followed by creating a piece, control-flow node or error handler can no longer reuse that child's ID. The regressions verify unique IDs after save/reload.
- **R2:** Deleting a detached parent transfers its child's authored coordinates into the promoted root. Root dragging retires stale per-step overrides. The node stays where it was promoted, moves to the new drop position and retains it after save/reload; Undo restores the original chain and position records.
- **R3:** The shared sample draft hook compares parsed JSON values for dirty state, so compact JSON stays saved after switching nodes. ## Integration for Lapo and the next agent

1. Keep the module unregistered until F-21, authenticated/scoped host integration and D-33 release verification are complete. No fallback from missing capabilities to fixture data is allowed.
2. The host can opt in using `workflowCanvasRegistration(useBinding, "workflow")` and the same registration for `"workflow-draft"`. Do not activate only one creation destination accidentally. `WorkflowCanvasBinding` requires source, account/vault scope, flow ID, exact editable version ID, current capabilities and a stable authenticated request function. Preview accepts fixture source only; live accepts live source only.
3. `workflowContext` must be ready/enabled. Route IDs must agree with the binding. `versionBoundRequest` rejects a different latest editable version before its response reaches the editor. It expects the existing editor API shape; F-21 compatibility still requires a real integration test when that provider lands. Historical locked-version inspection belongs to F-21/D-19, not this draft editor.
4. Scope the request to the actual account/vault/machine. The host owns credential handling, redaction and cancellation on ownership change. A flow/version/scope change remounts the editor; chat, theme and sidebar changes do not. Keep the binding's request identity stable during ordinary renders or the real hook will reload. Supply `onDirtyChange` to the host's room/account navigation guard. Also guard unsaved sample-editor navigation as part of live integration; this task proves retention across inspector and shell changes, not a cross-room draft store.
5. The real hook still reads the existing pieces, connections, workflow detail, library and scoped runs endpoints. Save and sample controls use their existing APIs. No extra execution API or catalog is introduced. Live library installation and per-step testing retain existing editor semantics and must use the host's authenticated request boundary; the isolated fixture rejects both.
6. `run` is an optional F-21-owned command. It must pin the intended saved version, collect explicit bounded manual input and reconcile an uncertain receipt before a new submission is allowed. The canvas never retries automatically. The illustrative preview acknowledges once locally and cannot run any workflow. A missing command leaves Run disabled.
7. A published-version save creates a new draft ID. The host must reconcile the returned canonical editable version and rebind/reopen it before another save/run. Never relabel the old version or silently switch historical run context.
8. Runs and Context preserve the selected flow/version navigation IDs. Their preview destinations are explicit handoffs, not invented run/context contents. D-19 and D-20 own those views. D-18 does not take over their scope.
