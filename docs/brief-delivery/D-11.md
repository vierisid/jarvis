## What changes

Today previously showed a static call-preparation card. It now uses a reusable opportunity stack with an outside heading/count, two restrained backing sheets, Next, Dismiss and **Approve & enable**. The card preserves the approved observation → prepared workflow → goal contribution structure.

Next changes the front proposal locally. A confirmed action acknowledges on that proposal, lowers it into the tray, reduces the count and settles the next available item. Dismissal has neutral feedback. The final item leaves a clear empty state. The hero, outcomes and goal do not claim progress merely because a workflow was enabled.

The preview includes the three existing native Figma examples. Real proposal copy is never inferred from legacy suggestions. An unavailable provider, incomplete preparation, stale snapshot or unavailable connection cannot show a working activation action. Nothing redirects to a creation prompt, executes a workflow or connects an account.

## Provider handoff for Lapo and F-track agents

The optional `OpportunityBinding` in `opportunity-stack/model.ts` is a presentation interface, not a new persistence schema or endpoint. It carries the F-01 `BriefPreparedOpportunity` unchanged, plus short owner-provided title/observation/automation/goal-title strings. `preparationReason` should name the actual missing setup. Do not use the UI's preview fixtures as a live fallback.

1. F-09 supplies the current prepared snapshot, its exact proposal ID/revision, evidence, goal ID/revision/rationale, composition ID, flow/version, readiness and required connection/device bindings. A library piece being installed does not establish credentials. The owner is responsible for complete binding enumeration and Q-13 freshness verification.
2. Supply a stable authenticated `scopeKey`, a `source: live` binding and a capability snapshot. `preparedOpportunities` enables reading; both preparation and `opportunityActivation` are required for actions. Preview accepts fixture sources only. Mount this view under Today's existing outside Opportunities heading. Remount when leaving an authenticated workspace; the scope key also fences asynchronous results.
3. `onAction` receives a random request ID and the exact proposal revision/action/flow/version being reviewed. The request ID is the owner's idempotency key. F-10 must recheck readiness, current goal, version, bindings and authority through its canonical services. Enable the reviewed version only. Activation must not also manually run it.
4. Resolve only after a durable outcome is known. A confirmed result must echo **all six request fields**, include a receipt ID and identify the correct enabled/dismissed outcome. Conflict, failure, transport loss and mismatched responses leave the proposal visible and locked against blind resubmission. Error details are not rendered from thrown exceptions.
5. `refresh` asks the owner for a fresh projection. It does not clear the lock. A new reviewed revision permits a new action. Optional `receipts` reconcile an outstanding request after a lost response. A matching authoritative confirmation cannot be downgraded by a late transport failure. The provider may remove or terminally mark a proposal before the action promise resolves without making this view skip another item.
6. Local attempt locks and settled identities survive temporary loading/unavailable reads while mounted. They are not durable idempotency or multi-window synchronization. F-09/F-10 must restore accepted/dismissed state after reload and enforce concurrency. This PR makes no claim to provide those backend guarantees.

Do not map a legacy draft-ready suggestion to ready/accepted automatically. The pinned `src/awareness/job-hypotheses.ts` explicitly distinguishes unverified hypotheses from confirmed jobs; `suggestion-composer.ts` attaches disabled drafts. Both pinned files are unchanged on this branch. Inspected main is `abb14deb59f1ca3a84227be9a2035687b29dea34`; open PRs were checked. F-09/F-10 were not implemented in this stack. Cross-track activation remains blocked until those owners and the D-33 release gate are ready.
