# F-25 — retained controls and navigation compatibility

Brief can keep its compact navigation without losing emergency, maintenance or recovery controls. This module resolves explicit destinations, legacy links and command/voice room requests; it routes attention rows independently of conversation visibility. It does not execute the action named by a destination.

## Composition contract

1. Retain one `NavigationCompatibility` per authenticated host lifetime. Pass a real `roomAvailable` probe, the shared async dirty-draft guard, synchronous commit and visible explanation callbacks. Call `setAccess` with authoritative capabilities; call `retire` on logout, scope replacement or host disposal. Late guards and older navigation requests cannot commit.
2. `browserNavigationHost` changes history in the same module lifetime and notifies both released routers. It preserves query/session parameters, removes the Brief opt-in for legacy destinations and hands Settings its canonical tab. It does not start a socket, microphone or second shell. Browser Back still belongs to the shell's route guard; compose it with D-29's `requestLeave` at D-33, not an unguarded room-local callback.
3. D-28: use `destinationPort(nav).navigate` for `advanced-authority` and `emergency-controls`. D-30: use `.callback(id)` for `authority`, `connections`, `voice-settings`, `advanced-settings`; cancellation rejects so D-30 cannot report it opened. Missing bindings keep the existing room gates closed.
4. D-27: bind `deviceNavigation(nav, freshSidecarSnapshot)` to `deviceDetails`, `manageDevice` and `addDevice`. Return `null` for an unavailable/stale snapshot. Updates/revocation open existing controls only; all effects and confirmation remain there. D-27's canonical F-22 read continues to enforce current permissions before handoff.
5. Route incoming room requests through `nav.intent`. By default they retain the canonical legacy room, because an old daemon can send a queued `room_action` separately. Pass `false` only for a verified navigation-only request. Do not acknowledge the action from this adapter: current main's canonical tab/action-result bus remains its owner.
6. Feed existing notification-owner rows through `fromNotificationCenter`; supply typed `failure`/`update` rows from the existing task/sidecar owners, with source IDs and timestamps. No text guessing, new fetch, new socket or storage. `AttentionRoutes` is the body for the host's existing attention outlet, outside the conversation subtree; keep the existing Needs you/sidebar entry available with chat closed. Opening marks a notification read only after successful routing, never resolves it. Stale/loading/unavailable counts are unknown, not zero. F-27 owns missed-event reconciliation.

The optional interfaces compile without D-27/D-28/D-29/D-30 imports. `scripts/check-f25-navigation.ts` additionally exercises actual pinned D-27/D-28/D-29 modules and current-main canonical voice tab names. The pinned D-30 Settings adapter is also exercised for opened/unavailable handoffs. Full dashboard composition is not claimed.
