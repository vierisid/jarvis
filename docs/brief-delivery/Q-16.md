# Q-16 — Correction and Forget consumer conformance

Q-16 closes stale memory consumption and re-ingestion gaps on the corrected F-19 stack. A prepared execution now checks canonical fact revisions and profile field revisions before another provider handoff or tool entry, regardless of usage logging. A changed execution fails with a refresh message; the next turn reads current memory. It never silently substitutes a value into approved work.

Replaying an automatic source revision of a superseded assertion returns its historical ID without creating another active assertion. This includes canonical extraction replayed through its legacy text-pair alias, changed extraction confidence/quote selection, unchanged profile-derived aliases, and goal-completion sources whose episode entity supplies identity without a source reference. A distinct source revision, changed profile field, or explicit confirmation can still introduce new information. Unidentified legacy inferences keep their existing qualified/contested semantics because they cannot be proven to replay the same input. Scope and validity periods remain part of assertion identity; model confidence never grants verification.

A profile paragraph containing a superseded derived fact is withheld from the prompt projection until the field changes. Editable settings remain available. The same revision check invalidates an already prepared paragraph. This can withhold other text in that paragraph; it is not a semantic rewrite of the source or of independently stored facts.

## Reproduce

Use this branch's pinned Bun **1.3.14**, frozen dependencies and an isolated temporary directory:

```sh
bun install --frozen-lockfile
bun test src/vault/memory-consumers.test.ts src/daemon/agent-service-memory-conformance.test.ts src/workflows/runtime/memory-usage.test.ts
bun x tsc --noEmit
bun build src/daemon/index.ts --target=bun --outdir=/tmp/q16-daemon-build
```

The focused suite uses local scripted providers and persistent SQLite fixtures, then closes/reopens their databases. It performs no external actions or paid inference. The exact wider command, verdict-only logs, baseline regression and review record are in [evidence/Q-16](evidence/Q-16/). The receipt is [Q-16.json](Q-16.json); exact published head, normal commit-hook results and CI are recorded in the PR description.

You can see this change on the Memory/Profile → chat/workflow consumer path, then run the focused command above: prepare context, correct or Forget the source, observe refused stale handoff and a fresh next-turn prompt while the historical workflow receipt stays unchanged.

## Limits and rollback

The checks cover canonical assertion identities, known source revisions, captured profile answers and dependencies in the bounded execution scope. They do not infer arbitrary paraphrase equivalence, remove copies from documents/messages/interview summaries, undo already dispatched tools, retract provider context, or erase independently stored assertions/backups. Original explicitly approved inputs remain historical, even if their text contains an older value. Full-form profile saves still express the existing API's replacement semantics; this card adds no settings conflict protocol.

After invalidation, refresh in a new execution; a reread inside the same execution does not erase its prior dependencies. Whole-block matching remains necessary only to claim a recorded provider supply event. Derived requests and legacy paths cannot manufacture usage provenance.

Rollback must retain F-19 tombstones and the correction/Forget guards. Disable new Forget requests with its existing flag if necessary, preserve all canonical records and history, and restore a reviewed bounded handler without bypassing invalidation. Do not deploy a pre-F-19 writer over a vault with tombstones, drop tables, erase work, or replay effects as rollback.
