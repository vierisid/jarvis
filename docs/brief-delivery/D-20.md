Missing context is never filled with configured values.

## What changed

The room reuses the shared workflow header, controls and materials. The wide view keeps goal/memory/connections opposite rules/target. With Pebble open, groups form a readable scrolling column. No dates, old subtitle or footer return. Source links use exact typed source IDs; labels stay short and IDs remain available to assistive text/hover and the destination resolver. Missing and removed sources have no fake open action.

`WorkflowContextController` is scoped to owner, flow and configured version. Configured and recorded reads have separate cache keys; a late result for one never appears under another. Responses must match the requested scope, basis and run; configured version mismatches fail closed, while historical run versions remain intact. An optional expected run version can also be checked. Read errors are distinct from empty data. Failed refresh preserves explicitly stale evidence; retries coalesce while pending. Room/basis return refreshes the projection while retaining its own scroll position. The host retains the controller across shell changes and retires it on ownership change.

The presentation validator whitelists fields and strips marked-redacted label/content/source before caching. React renders values as text. Per-group unavailable, unsupported, loading and stale states remain visible without replacing them with another group's facts. This is defense in the UI, not a claim of backend authorization or redaction certification.

The optional header command uses the **same D-19 run controller** as Runs. A matching receipt selects its exact run in Runs; an uncertain acknowledgement stays locked across room returns. A late response cannot navigate an unmounted room or replaced command owner. A new queued run may have no context yet, and that state is shown explicitly. Canvas retains its D-18 integration contract; it needs the same durable command owner at live cutover.
