## F-05 integration handoff

The structural adapter matches F-05 `f98cd312ca0b450bb5180320fc8c0491757cae67` ([PR #740](https://github.com/vierisid/jarvis/pull/740)); it imports no unmerged feature files. Reuse the existing single conversation provider. Its client supplies `getSnapshot`, `store.getSnapshot`, `attachments.upload` and `attachments.capture`.

```tsx
const attachmentBinding = bindAttachmentFan(thread.client, pickers, "live");
<ConversationComposer mode="live" binding={composerBinding}
  attachmentControl={<AttachmentFan mode="live" binding={attachmentBinding}
    onFeedback={message => setLocalStatus(workspaceId, conversationId, message)} />}
/>
```

The host supplies `AttachmentPickers`:

- `file(kind, signal)`: show the native picker on an explicit action. Return the selected File or null; discard late results after signal abort. Do not persist bytes in localStorage.
- `screenshot(signal)`: show connected capture-capable devices and obtain explicit confirmation. Return `{ deviceId, confirmed: true }` or null. Availability comes from the existing capability/device read model, never the browser name. Never silently capture another device.
- `onFeedback`: render in a reserved accessible status area for the originating workspace/conversation. Cancellation produces no success receipt. Generic failures do not expose backend internals.

The adapter captures workspace/conversation before the picker, then rechecks capability, connection, metadata writes, workspace and open-tab identity before dispatch and after completion. Active-tab changes cannot redirect files. Closing the original tab, changing workspace or aborting refuses late dispatch. Undefined/superseded F-05 completions cannot produce an attached receipt.

F-05 owns reference states, retry/remove, validation, permission and send admission. The integrated host must render those references and retry/remove controls. Failed uploads must be retried or removed through F-05. Use its send path with attachment IDs and readiness checks. D-13's standalone text composer still needs combined attachment-readiness/file-only-send integration before activation. This task supplies entry and delegation, not an enabled end-to-end attachment product.

The body portal follows the invoking theme and measured origin through shell reflow. It becomes inert on close and hides with Pebble. Clipping above the toggle prevents emerging rows from intercepting it during reversal. Unsupported Screenshot remains focusable to expose its reason but cannot dispatch.

## Review fixes: R1 and R2

The review of `f78e705415e13f6c230e4cea013899c0807c6818` found two reproducible issues. Both are corrected in the same D-14 branch and PR.

- **R1, cancelled selection after a chat switch:** keyed fan cleanup marked its callback inactive before aborting the request, leaving the originating conversation's Adding status behind. Abort now clears only the captured conversation's pending status before callbacks are retired. A completed status in another chat remains intact, and the old request cannot overwrite a later result.
