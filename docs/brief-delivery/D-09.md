## What changes

Today now uses dedicated outcomes and activity components instead of local layout-only markup. The approved large time/partner figures, wide day chart, compact composition and Recent activity below outcomes remain recognizable. There is no Time back heading or weekly estimated suffix. The daily estimate keeps its qualification; Data basis exposes owner-supplied attribution, coverage, timezone/window, evidence counts and as-of dates, including in the compact layout.

Goal bars share ten asymmetric segments and the approved UI-06 bands: below 20% red, 20–39% amber, 40–74% blue, and 75% upward green. Remaining segments are gray. Weekly positive change is a separate green signal, not a completion band. The preview main goal reuses this same treatment; its actions and drivers remain D-10 fixtures.

A refresh fades only changed digits over 180ms. It never counts up from zero or animates unchanged figures on mount, navigation or chat opening. Numeric slots reserve room for the denominator's digit width, including 9/10 to 10/10. Day bars use a stable owner-provided scale, mark overflow explicitly, and expose concise values on hover or keyboard focus. Reduced motion immediately uses the same final values.

Activity has three columns when wide and stacked rows when compact. Entries remain informational unless the owner supplies both a destination and a navigation handler. An actionable row has one full-row target and quiet focus/hover feedback. Source IDs pass through unchanged.

## Ownership and integration handoff

Owned code:
- `ui/src/brief/today/outcomes/`: read-only panel, value/segment presentation, qualification guards and tests.
- `ui/src/brief/today/activity/`: read-only activity list.
- `today/preview/`: minimal isolated composition and representative examples.
- This task's guide, receipt and evidence.

The stack reuses D-02 tokens, D-03 controls, D-04 motion/reduced-motion rules, D-06 host and D-07 Today slots. It introduces no global routing registration, storage, endpoint, subscription, analytics query or writer. The owned modules do not import fixtures. Preview data stays under the explicit isolated-preview entry.

F-16 must provide the `OutcomeSummary` aggregate and `RecentActivityItem[]` through `OutcomeBinding<T>`, using F-01's `BriefMeasurement` and read-state vocabulary. These are optional UI-facing types, not a new HTTP schema. Integration should supply `<Outcomes mode="live" binding={qualifiedOutcomes} />` and `<RecentActivity mode="live" binding={recentActivity} onOpen={navigate} />` through the existing Today slots.

Required owner responsibilities:
- Supply canonical totals, stable goal/day/activity IDs, a reporting window with timezone and a stable chart maximum. Format activity time labels in that timezone.
- Distinguish loading, unavailable, unsupported, stale, empty and partial data. Retain timestamps/evidence with stale data. Use null for unknown measurements, never an invented zero.
- Establish baseline methodology, sufficient evidence, qualification and truthful attribution before marking a measurement ready. A nonempty provenance array is only a display guard, not proof that the evidence is valid.
- Provide time saved in minutes with a finite nonnegative value and a finite baseline at least that large. Supply finite goal values and a positive target; do not map a review score onto signed partners.
- Own durable deduplication, revisions, reporting windows and reconciliation. Supply sanitized concise basis text. Evidence references are counted here; this PR does not implement source-document retrieval.
- Provide a real activity destination only if it can be opened safely. No destination/handler means no actionable styling.

The live seam requires source `live` plus ready/enabled `outcomes` and `goalMeasurements` capabilities. Missing owners or capability loss hide the values. Preview mode accepts only fixture sources. The source guard prevents accidental mixing; it is not an authorization boundary.

**Activation dependencies: F-16 qualified outcomes, F-15 measured goal progress, the existing Today/shell/navigation dependencies, and D-33 release approval.** F-16 owns aggregation and qualification; D-09 never subtracts engine runtime, sums workflow runs, or derives business progress from goals. Engine duration is not time saved. The new components remain gated until their integration is independently verified.
