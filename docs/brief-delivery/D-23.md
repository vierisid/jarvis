## State and action behavior

`DecisionsController` belongs to one authenticated scope, retained across room mounts. The room uses the shared Today `DecisionPaper`, stable decision ID, approval/work-item route aliases, source-owned action labels and exact revision. Layout/theme changes do not recreate the owner. Selection and independent reading positions survive a return to the room. Canonical approval rotation after a saved revision does not change the stable decision identity.

`DecisionsPort.read` supplies the complete authorized queue with revision-aligned document projections, not raw tool arguments or the first page of a paginated list. Loading, empty, stale, unavailable and unsupported remain distinct. This presentation adapter handles F-14 document permission actions only. Intent and execution-recovery decisions, rich/opaque unsupported documents and unsupported edits stay read-only with an owner-provided explanation and source route. It does not invent acceptance or execution policy.

Editing buffers a complete typed email/calendar document. Body, recipients, subject, calendar dates and readonly service options remain visible. Read/edit share mirrored field geometry; longer text grows naturally without hiding controls. Save requires a current matching revision and valid supported fields. A fresh read that changes or removes the original decision keeps unsaved content available but disables Save. Cancel discards only the local edit and refreshes. Saving does not approve; a new approval revision must be read and reviewed separately.

Each action captures stable ID, revision, action and one request ID before dispatch. In-flight writes lock duplicate/opposing actions synchronously. A matching F-14 receipt must contain the same request/decision, the expected outcome, an approval ID, result revision/generation and `executed: false`. The result revision is not assumed to equal the submitted revision. Permission granted is explicitly **Sending has not been confirmed**. Keep draft says Nothing sent and retains the deferred row with an explicit Reopen action. Rejection has a separate local message. A rejected workflow blocker retained by the canonical queue is not hidden as successfully resolved.

Unknown requests keep their original document/slot through refreshes that omit it. Check result reads the original request receipt and never repeats the write. Definitive adapter-certified refusal requires an explicit fresh read before retry. Local acknowledgement lasts 520ms (immediate placement under reduced motion), then a fresh queue selects a surviving captured successor. A user-selected different decision stays selected. Fresh projection/result-revision disagreement blocks actions until another explicit refresh; stale receipts never authorize a new approval.

The controller preserves a known request while mounted, but is not durable storage. **Persistence and shared Today/Needs you ownership are activation gates**, not implemented backend features.

## Review corrections (7 October 2026)

- **R1:** Completed receipt reconciliation is idempotent. Check result disappears once settled; calling recovery for that historical request cannot replay acknowledgement or clear a subsequent edit. A save releases only the exact submitted edit snapshot. Failed projection reads still allow read-only recovery, and text changed during reconciliation remains available.
- **R2:** An active edit stays pinned independently of any earlier confirmed attempt. Removed, unavailable and changed canonical projections retain the original document, unsaved text and Cancel edit, while Save remains disabled until a current revision is reviewed. Successful save reconciliation uses the canonical projection rather than the pinned editing copy.
- **R3:** Automatic advancement checks a selection version across the refresh. A decision chosen while that read is pending stays selected.
