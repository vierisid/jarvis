# Q-15: Founder memory recall

Queries naming a person in full could include another person's contact or meeting facts because a shared name token and generic task words scored above the relevance floor. Q-15 scopes **person facts** when a multiword person name occurs in order in the query. Other people need an explicit name/qualified alias or a fact directly referencing the requested person. A direct reference admits that fact and its required contradiction evidence, not all facts belonging to its subject. Non-person task subjects keep their existing ranking. Omitted records remain disclosed.

This changes relevance selection only. Canonical fact/evidence writers, stable IDs, verification, contradiction, validity, correction history, `queryFact` binding rules, qualification formatting and packing limits are unchanged. Recall remains qualified context, not permission to act.

## Frozen evaluation protocol

`founder-recall-v1` uses 12 development cases and 20 heldout cases, each in original order and two fixed shuffled insertion orders. Each case has one query. Cases cover meeting preparation, shared first/last names, absent contact details, expired/future/corrected preferences, contested and unconfirmed bindings, sparse memory, long histories, context omission, Unicode/CJK, qualified aliases, scopes and duplicate names.

Fixtures are synthetic and author-visible. Twelve heldout scenarios reuse development templates with different identities; eight add further scenarios, so these are not 20 independent task families. The heldout set was authored before tuning, but not executed until the development candidate was frozen. It is **not an independent or blinded sample**. Its first matched result is retained; the heldout tests added afterward are regression tests. An initial development-only harness preflight corrected the contested-binding expectation to abstention before the corpus freeze. There were no heldout-driven runtime edits.

Each matched comparison runs both implementations through the same harness, corpus, clock, token encoding and canonical writers. The original reports use the frozen harness; corrected scoring-v2 reports live separately under `evidence/Q-15/review-fixes/`. Deterministic fixture UUIDs preserve fact and evidence references across order shuffles; independent fact bundles shuffle while corrections retain causal order. Before/after ledger hashes reject recall writes. Reports identify every included fact and its complete ledger evidence IDs, and every omitted fixture fact with a reason. Those ledger IDs do not assert that all evidence was packed: the unchanged formatter supplies the strongest three summaries and the fact ID remains the ledger lookup handle.

Qualification checks now require every occurrence of each canonical formatted fact to remain under its canonical subject heading, plus the memory-use preamble. Mutation tests deliberately inject a wrong-person record, strip qualification/preamble, remove answers and overflow the budget. Binding checks call canonical `queryFact`, independently of prompt inclusion. Comparison rejects unmatched protocol/corpus/harness/observation sets and detects retrieval/safety regressions.

Token counts use pinned offline `js-tiktoken@1.0.21`, `cl100k_base`, on the memory block only (special-token-looking text is ordinary input). The fixture gate is 4,096 reference tokens plus the existing 12,000 UTF-16-character maximum or a smaller case cap. This measures these cases; the runtime still enforces its character budget, not a universal 4,096-token cap. No hosted model, billing profile, full prompt, paid evaluation or real user vault was used. The tokenizer is a development dependency and is not imported by the daemon.

## Matched results

Headline fact/binding/token rates use original insertion order only. Shuffles are paired robustness checks, not extra independent samples. Case success requires all orders to pass. The machine-readable reports include descriptive Wilson intervals; fact observations within cases are correlated and these intervals do not establish population accuracy.

| Measure | Development baseline → candidate | Heldout baseline → candidate |
| --- | --- | --- |
| Cases passing every order | 8/12 → 12/12 | 15/20 → 20/20 |
| Relevant fact inclusion | 12/12 → 12/12 | 23/23 → 23/23 |
| Relevant / included facts | 12/16 → 12/12 | 23/28 → 23/23 |
| Wrong-person facts included | 4 → 0 | 5 → 0 |
| Exact qualification retained | 16/16 → 12/12 | 28/28 → 23/23 |
| Correct canonical bindings/abstentions | 6/6 → 6/6 | 8/8 → 8/8 |

Heldout: **60 matched observations, 15 improved, zero regressions or safety failures**. Candidate fact/evidence identities and exact context hashes also remain identical across insertion orders. Heldout case success's descriptive Wilson 95% interval is 83.9–100%; this small authored corpus does not justify a claim of universally safe recall. Latency samples are included for reproducibility, not a performance gate or deployment estimate.

## Review corrections

The follow-up review found three defects: full stored fact text was normalized once per named person, subject-heading corruption escaped evaluator scoring, and a substring filter hid facts whose value or evidence contained `No current facts recorded.`. All three are corrected. Names are normalized once per entity and fact fields once per scoped fact; every rendered occurrence is checked against its canonical owner and exact formatted fact; only the exact empty-record marker is excluded. Duplicate corrupted occurrences also fail.

Four regression failures reproduced the reported defects before the fixes. All five added tests now pass, including the unchanged sparse-memory marker. The full vault suite passes **203 tests and 1,124 assertions across 18 files**. TypeScript, the 1,263-module daemon bundle and normal commit hooks pass. The final read-only Review Agent pass found no remaining actionable issues (implementer review, not independent approval).

`founder-recall-scoring-v2` identifies the corrected evaluator. The unchanged baseline and corrected candidate were both rerun with it. The table above is unchanged: every context hash and included fact/evidence identity matches the corresponding original report, and both comparisons pass without regressions or safety failures. These are **post-review regression re-evaluations**, not another unseen heldout evaluation. The original corpus, freeze files and first reports remain intact; compare only reports with the same scoring version and harness hash.

The local stress case uses 300 people, 3,000 facts of 1,919 characters each after canonical trimming, and 25 named people in a 396-character query. Median ranking time fell from **1,926 ms to 252 ms**; the older main baseline was 158 ms. Complete pre-fix and corrected ranking output is identical. Normalization calls fell from **423,303 to 18,453**. CI guards the operation count rather than wall time. These local samples are not a daemon-latency or production-load guarantee. Reproduce with:

## Limits and rollback

This is lexical relevance, not semantic identity resolution. Partial names, single-token names, shared aliases, pronouns and facts incorrectly attributed at write time retain their existing limitations. Duplicate full names remain ambiguous; no identity merge or confirmation is inferred. Real founder-task distribution, multilingual breadth, deployed providers, F-18 usage capture and Q-16 cache/forgetting propagation remain unmeasured here.

Rollback restores `src/vault/recall-ranking.ts` from baseline `8a0da716` and reruns the established recall tests. Keep canonical qualification/contradiction/validity guards and all stored facts/evidence. This restores the prior bounded relevance policy; it does not replay effects, mutate memory or erase history. The new founder regression will correctly expose the prior wrong-person limitation after rollback.
