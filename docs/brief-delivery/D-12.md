## Handoff to Lapo and the F-04 integrator

The structural `ConversationTabsOwner` interface matches F-04 at `72f3078a4857e28ae6738c336f55f2988bf6f31b` ([PR #738](https://github.com/vierisid/jarvis/pull/738)). It avoids a hard import of that unmerged branch.

At the eventual authenticated workspace composition root, mount F-04's `BriefConversationProvider` exactly once above rooms. Keep the selected conversation content with that owner. Do not mount a second WebSocket or copy messages/drafts into this strip.

```tsx
const thread = useBriefConversation(); // F-04, available only after its integration
const binding = bindConversationTabs(thread, "live");
const panelId = "brief-conversation"; // unique for this mounted panel
return <>
  <ConversationTabStrip mode="live" binding={binding} panelId={panelId}/>
  <section id={panelId}
    role={thread.status.mode === "scoped" && thread.current ? "tabpanel" : undefined}
    aria-labelledby={thread.status.mode === "scoped" && thread.state.activeId
      ? chatTabId(panelId, thread.state.activeId) : undefined}>
    {/* Existing owner-supplied content, including the real single-chat fallback. */}
  </section>
</>;
```

- Only `status.mode === 'scoped'` with a workspace ID exposes metadata actions. Wrong live/fixture source, absent binding, loading, legacy, disabled and unavailable states expose no fake tabs. Preserve the actual legacy content below the fallback header.
- The strip calls only `client.add/select/close`. F-04 serializes these writes. It chooses adjacent selection, keeps closed history, and owns reopen access. No cancel/send/delete method is accepted by this UI port.
- `activeId`, titles and order are authoritative. The strip does not optimistically create/delete conversations or guess the new selection. It blocks repeated writes while awaiting a result; failures are acknowledged locally. The component resets local interaction state for a changed workspace ID and ignores late errors after unmount.
- F-04 chooses the right neighbor, otherwise left, otherwise null. This replaces Figma's older final-close New chat example. A new history is created only by +. The existing F-02 history/reopen affordance must remain available when integrating the owner.
- The caller owns the panel ID/ARIA relationship and per-chat content/scroll restore. Keep the provider above room/theme/sidebar/Pebble transitions, keyed to the authenticated owner as F-04 requires. Never key conversation state to a tab index or title.
- The strip fits the existing Pebble shell content inset and reserves 36px for the shell-owned 44px X. Text is clipped, never scaled. Width changes use D-04's interruptible 180ms motion controller. A local animation-frame loop keeps the selected/focused tab visible while geometry changes; reduced motion places it immediately.
- Keyboard navigation uses manual activation to avoid triggering metadata writes on every arrow key. Close X is a sibling button, not nested inside a tab button. The focused close/selected tab recovers to the owner's selected neighbor; remote updates do not take focus from a composer.
