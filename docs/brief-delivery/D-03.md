# D-03: Shared controls for the Brief dashboard

Brief now has its own buttons, icon actions, links, fields, native selects, switches, tabs, segmented choices, tooltips and menus. They replace the D-01 button bridge and give later room authors a common interaction vocabulary. The released dashboard remains the default; this PR does not register new live rooms or change domain behavior.

## Quick verification

Build this worktree with `bun run build:ui`, then run `python3 -m http.server 4383 --bind 127.0.0.1 --directory ui/dist` (or another free port).

Open `http://localhost:4383/?brief=preview&specimen=controls#/_brief_preview`.

1. Try **Light/Dark**, **Wide/Narrow**, and **Standard/Compact**. Fields, controls and menus share the chosen appearance. These choices affect only this reference.
2. Clear **Full name** and choose **Save changes**. The error takes reserved space. Fill a name and save again: Saving / Changes saved / Try again occupy the same button width. **Simulate a failed save** demonstrates retained input and retry feedback.
3. Edit **A retained draft**, visit **Completed**, then return to **Active**. The value stays. Arrow keys move tab focus; Enter or Space selects. The disabled tab is skipped.
4. Toggle **Workflow activation** with Space or Enter. Enabled/Paused follows the thumb. Disabled-on and disabled-off examples keep their position but look unavailable.
5. Hover or keyboard-focus the small X/bin. The tooltip appears after 500ms on hover, immediately on focus. Move onto the label, then away; Escape also dismisses it. Delete opens an illustrative local confirmation with Cancel/Undo, not a real deletion.
6. Open **Account example**. It extends outside its clipped container. Try arrows, Home/End, typeahead, Escape, Tab and outside click. **Next control** provides a visible keyboard return target. The menu entries only update a local message.

Use the normal URL without the Brief query parameters to return to the released dashboard. This static preview needs no API key, hosted brain or account connection.

## Integration contract for Lapo and other agents

Import from `ui/src/brief/components/controls`. Mount inside `brief-root`, with the existing inherited appearance or explicit `data-brief-theme`. Importing the barrel loads only scoped Brief control CSS.

| Control | Caller responsibility | Behavior supplied here |
| --- | --- | --- |
| BriefButton | Pass an action, state and all possible `stateLabels`; primary/secondary/text/danger role | Native button; default type=button; pending retains focus and blocks repeated click/submit; labels reserve maximum width |
| BriefIconButton | Supply a concise `label`, icon and destructive intent where appropriate | 44px or 36px target around a 16px glyph; tooltip; neutral bin at rest, warning color on intent |
| BriefLink | Supply a real href | Native link; stationary label, 3px directional arrow shift |
| BriefInput / Textarea / Select | Native value/onChange or defaultValue; label, hint/error/saved; `reserveMessage` for the longest known validation text | Label association, invalid/described-by state, fixed adornment slot and at least 32px feedback space; native select keyboard behavior |
| BriefSwitch | Controlled checked value and callback; domain-specific `onLabel`/`offLabel` | Native button with switch semantics, 20px thumb travel, unchanged position when disabled |
| BriefTabs | Stable item IDs, panels, selected value and callback | Manual activation; arrows/Home/End focus, Enter/Space select; disabled entries skipped; hidden panels remain mounted |
| BriefSegments | Controlled value, stable options and group label | Independent native radio group; equal widths and full-label targets; selected stronger than hover |
| BriefMenu | Stable item IDs, labels, callbacks and disabled/destructive intent | Top-layer portal, local theme inheritance, keyboard navigation, typeahead, outside dismissal and focus return |
| BriefTooltip | One semantic focusable child and a short description | Hover delay, immediate focus, Escape, pointer bridge; no replacement for essential always-visible instructions |

Reserve feedback for the actual longest authored error, not an invented global maximum. Arbitrarily longer runtime text must expand rather than clip. Likewise, translated action labels must be included in `stateLabels`. Pending is presentation and a local duplicate-click guard, not server idempotency. Native-disabled controls are not keyboard focusable; explain important unavailability in visible adjacent text.

Tabs preserve mounted component state; they do not provide persistence, backend conversations, conversation closing or a product chat-tab policy. The menu is a small action menu, not a searchable library picker or a nested navigation system. Callers should keep labels concise. Later room PRs still own their exact layouts, labels, action destinations, async lifecycle and errors.

## Geometry, appearance and motion

Controls use the approved 8/0/8/8 corners. Buttons are 40px/32px with 14px/13px labels; inputs are 44px/40px; the 44×24 switch has an 18px thumb and 20px travel. Focus is a 2px edge offset by 3px, without a padding change. Fields reserve their label, adornment and helper space. Off and disabled differ through both position and tone; adjacent meaning labels remain visible.

Surfaces and ink update together on a theme change. Browser QA caught an initial animated-tab contrast dip, so control color interpolation was removed. Switch translation and link-arrow motion retain the local 160ms ease and honor reduced-motion CSS. D-04 owns the shared movement system and instrumented interruption/reduced-motion verification; this PR does not claim to complete it.

Menus/tooltips portal to the body and use the Popover API top layer where available. Theme changes are observed from the invoking Brief root and document. A body portal remains the fallback in older hosts. Menus use the D-02 menu material; tooltips use the approved black surface in both themes. Tooltip padding provides the icon-to-label bridge, and a focused tooltip stays visible when the pointer leaves.
