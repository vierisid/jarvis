Forget requires a local confirmation of its actual scope. Returning restores the applied query, loaded window, scroll position and focus to the original fact, its replacement or its nearest remaining neighbor.

## Design and interaction

The native [Memory detail frame 382:4043](https://www.figma.com/design/eNfKeirIKLZLlZEasrurZa/Jarvis-Brief-Working-design?node-id=382-4043), page `81:2`, and UI-35 handoff `898:379708` / coverage `898:379724` were inspected in Figma. Native screenshots are retained. The sentence, quiet back control and action row preserve the hierarchy; source/use/history remain subordinate. Confirmation and reason fields adapt the reference to the real writer contract.

The sentence transfers by position using D-04's 280ms token without scaling text. Cancellation disposes its animation; the OS reduced-motion media query skips the transfer. Return uses restored geometry, focus and a static 1.6-second row highlight. Browser entry/settled coordinates and screenshots demonstrate the forward path; they do not certify frame rate or interrupted velocity continuity.

Full text, qualifications and source references wrap at narrow widths. References are displayed as text, never arbitrary links to execute. Editing keeps the assertion, action row, note and feedback space stable when a conflict removes stale canonical content. Browser testing found and corrected both a disappearing-note jump and a narrow wrapped-action jump; final before/after field and button coordinates match exactly. Cancel discards the draft and restores action focus without a write.

The stream retains its controller and filters across detail navigation. Before a possible mutation, cached rows are invalidated. Return refreshes the previously loaded bounded window, then selects the replacement, original, nearest surviving next/previous row or Search when nothing matches. All memories and the shell breadcrumb share this behavior. A corrected fact whose new provenance no longer matches Source correctly disappears from that filtered result.

## Contracts and activation limits

`memoryDetailRegistrations(useBinding)` supplies the optional `memory` and `memory-detail` pair. Retain both controllers per authenticated scope; retire them on logout/scope replacement. The binding must match scope and live/fixture mode, and live mode requires `memoryStream`, `memoryUsage` and `memoryForget` readiness. Never register the specimen as a production fallback.

The HTTP port uses authenticated, no-store F-17 detail/history reads and the existing canonical fact reader. It brackets the canonical read with F-17 revision reads, rejects changed or mismatched records, validates bounded history, and enforces current permissions. Access loss, missing/forgotten history, scope replacement and late responses cannot restore stale content.

Correction/confirmation uses `/api/vault/facts/:id/correct` or `/confirm` with explicit `confirmed: true`, value where applicable, and reason. It rereads permissions and compares the displayed revision before POST. The writer owns supersession and preservation of earlier evidence. **F-17 currently advertises `canCorrect: false`; this implementation preserves that restriction.** The legacy writer does not accept an atomic expected-revision precondition. This UI preflight is not atomic CAS; production correction permission readiness and concurrent-write semantics must be verified by the integration owner before enabling writes. No new backend writer or permission override was added.

Forget uses F-19's prepared digest, which is deliberately different from F-17's usage-inclusive revision. It checks the prepared scope, rereads the displayed fact, and submits one explicit command with request ID and expected revision. An ambiguous save never automatically resubmits. An ambiguous Forget clears cached content and offers a GET receipt check. The controller rejects unknown future scope variants rather than displaying misleading deletion claims.

The confirmation explains that Forget removes only the selected canonical fact/evidence and future recall; source replay suppression applies to the same revision. Original messages, documents, backups, other facts/history and entity relations remain. Editable profile/interview sources, content-free receipts and usage remain; matching profile fields are withheld until changed, and already-sent model context cannot be recalled. There is no Undo. Browser tests mutate only disposable in-memory fixtures.

Before activation, verify the real authenticated F-17/F-18/F-19 deployment, correction readiness/concurrency, F-19 durable receipts and restart suppression, logout/reconnect and canonical invalidation. Those deployment checks are **not_run** here. A real canonical correction is tested against an isolated SQLite database, including reopening it and verifying the original evidence; the F-17 projection in that test is injected, not a claimed full-stack deployment.

## Review corrections

The review of `2371d272898577a2d0fdc3d2c02294a9e7cf6f22` found three defects, now covered by 16 added regression tests:

- A denied detail or Forget preparation read could leave the cached stream accessible. Unavailable reads now clear the detail, history, editor and prepared command and invalidate the stream. This applies to both Forget preparation requests; 401, 403 and conservatively 503 responses are tested through the HTTP port without relying on message text.
- A successful correction followed its replacement inside the controller but left the shell route on the superseded ID. A pending replacement now survives room remounts until the shell acknowledges the new selection. Later inspection of an earlier value remains possible, and a late save cannot replace a different selected fact.
- Canceling an in-flight history request left its loading state stuck. Cancellation now resets only pending history, preserves completed history and rejects late responses, so Show earlier values can be retried after Cancel, Forget preparation or a rejected save.

Validation after these corrections: **126 memory tests / 483 assertions; 677 Brief tests / 5,525 assertions, with two existing optional skips; TypeScript, UI build, formatting, diff checks and normal commit hooks pass.** Review logs use the `review-` prefix under [evidence/D-26](evidence/D-26/). The retained before-fix log intentionally records 14 failing regression cases against the reviewed code. These controller/route changes were verified with deterministic HTTP/controller and React tests; the original browser layout/motion captures were not rerun for this correction pass. Activation limits remain as recorded above.
