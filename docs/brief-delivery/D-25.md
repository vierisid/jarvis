## Read contract and integration

`MemoryController` owns one authenticated scope. Retain it across room mounts; retire it on logout or scope replacement. A capability revocation cancels outstanding reads and clears rows and sensitive filters. Ordinary refreshes and errors preserve applied filters. A new query, stale cursor or failure clears old rows: forgotten facts must not remain visible as stale cached content.

The optional `memoryHttpPort(scopeId)` sends authenticated, no-store GET requests to `/api/brief/memory`. It preserves canonical IDs, permissions, provenance and usage evidence. It does not introduce a memory engine, writer, new endpoint or backend dependency. Pages are validated as a whole; dropping unreadable rows would falsify counts. Rows sort by Updated descending, then canonical ID ascending.

- Search is literal text, limited to 256 characters. Source is an exact label, up to 4,000 characters. Used in accepts `conversation:<id>` or `run:<id>` and excludes selected-only evidence. Updated uses inclusive `updatedFrom` and exclusive `updatedBefore` UTC milliseconds.
- Requests use 50 rows. Continuation repeats the frozen filters, time bounds and page size with the opaque cursor. The controller checks ordering, duplicate IDs, exact total/matched counts and complete pagination. `count.returned` remains the wire page's count; the accumulated list length is shown separately.
- F-17 freezes membership for five minutes. Correction, deletion, provenance/usage changes, expiry, restart or eviction can return 409 stale without content. Refresh without a cursor. Provider/dependency/capacity failures are unavailable; missing routes/providers are unsupported. None falls back to fixtures.
- F-17 bounds the complete input to 10,000 fact rows including history, 50,000 evidence rows and 50,000 usage records, with separate 16 MiB fact/provenance and usage bounds. Beyond capacity the UI shows unavailable, never partial-vault counts.
- Usage means retained provider handoff, not model reliance or verified outcomes. Unknown, no retained use and selected-only evidence are distinct. F-18 retains bounded evidence for 90 days and reports limited instrumentation coverage; this room does not manufacture historical associations or outcomes.

To integrate, supply `memoryRegistrations(useBinding)` behind the authenticated Brief release gate and ready **both** `memoryStream` and `memoryUsage` capabilities. The binding and controller must share scope and live/fixture mode. Construct the HTTP port only for the real authenticated F-17/F-18 deployment. Supply authorized source/use suggestion catalogs if available; exact entry works without them. Refresh on reconnect and canonical changes. Keep this controller scoped to the host session, not browser storage.

An optional `onOpen(factId)` carries only canonical identity. The host's D-26 detail owner must reread current canonical data and enforce its permissions. Without that owner the row is visibly/focusably unavailable through `aria-disabled` and a detail-unavailable title. The fixture merely reports the selected ID; it implements no detail/edit/forget flow.

Before activation, verify authenticated real queries, exact counts beyond the first page, combined filters, unavailable usage, stale cursors after mutations/restart, capability revocation and logout/scope replacement. This card's HTTP tests use injected responses; live F-17/F-18 integration is **not_run** because the default-off F stack has deliberately not been imported or activated.

## Review corrections
